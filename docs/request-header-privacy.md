# 上游请求头隐私

模型调用默认使用统一的 `User-Agent: opencode`。客户端原有的 Claude Code、Codex、SDK、设备与转发链标识在进入供应商之前清理。会话／代理标识在服务器映射成稳定的匿名值，继续保留同一会话的账号粘性。

CommandCode Provider 请求在最终出站处处理；CPA 使用原生提供器执行时，也对其原生上游配置和凭据来源应用软件标识策略，避免执行器重新覆盖成原客户端 User-Agent。Codex 关闭内核的最后一层客户端模拟，并使用 `Originator: opencode`；官方 Google 提供器的客户端说明头也使用 `opencode`。

部署更新会设置现有来源的默认值。平台管理接口新增或修改来源后重新应用策略；平台分组选择来源时，在实际调用前再次核验和应用。已有账号配置、令牌、刷新令牌、模型别名、工具字段、代理和未知元数据保留。配置数组更新使用与渠道维护相同的服务器锁，凭据文件先使用原生字段更新；同文件的多个虚拟账号通过源文件更新共同生效。

此设置处理请求头，不修改对话、提示词、工具参数或用户主动填写的请求体。供应商仍能看到提供器协议必需的认证、账号和版本／Beta 能力头。Claude OAuth 的 `X-App: cli` 由原生内核保持，来源里的旧客户端覆盖会移除。旧配置中的 SDK 版本、运行时版本、OS 和架构默认值会清空，恢复内核自身的统一兼容默认值；CPA 为某些 OAuth 协议自行生成的 SDK 兼容头继续保留。因此不能把这项设置理解成请求体匿名化或隐藏供应商本身需要的 OAuth 账号身份。

保留必要协议头后，流式响应、OAuth 刷新、工具调用和配额查询继续使用官方 CPA 内核。模型插件使用官方 SDK 的 `host.net` 出站时，内核也统一覆盖软件标识并清理调用方设备、追踪与转发链信息；嵌套模型调用继承相同策略。供应商凭据与调用方标识分别处理，调用方的 Cookie 不进入供应商请求。

插件自行绕过官方 SDK 直接建立网络连接时，其内部出站行为由插件自身实现决定。市场保持原版插件接口和完整角色支持，安装前可查看插件来源、许可证及声明能力；请求头设置不改变插件的程序权限。
