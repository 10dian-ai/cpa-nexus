# CPA Nexus 平台范围

确认日期：2026-10-03。

CPA Nexus 是基于 CLIProxyAPI 的模块化 AI 管理平台。完整官方 CPA 独立运行并处理模型调用流量；统一面板提供原生管理能力和扩展模块管理。当前 CommandCode 账号池是第一个扩展模块。

当前账号方案为 GOAT 官方 Provider API：Cookie 只用于账号管理及 Key 获取，推理使用专用 API Key。原 Go 私有协议适配器保留历史源码，不参加默认部署或构建。

## 模块契约

模块在 `shared/modules.ts` 注册稳定 ID、名称、版本、能力和导航。平台与 CPA 核心是必需模块；业务扩展可以停用。停用只影响新模型请求、新导入和新后台任务，进行中的请求和任务继续完成；账号数据保留，读取和管理入口保留。

模块状态写入 PostgreSQL。多个应用与 Worker 最迟在状态缓存的两秒有效期后观察到修改；刷新队列中的工作会延后并保留检查点。停用期间账号相关写入操作也暂停，已有账号、日志与任务结果仍可读取。

CPA 核心的 API 版本适配集中在 `server/lib/cpa/`。业务模块通过自身上游适配器或 CPA 插件接入；模块化不要求每个功能启动独立容器。

## 首版已实现的管理入口

- 实际核心连接、运行版本、构建与插件支持信息；候选更新查询。
- 原生配置 JSON、YAML 和配置节点管理。
- 原生凭证上传、下载、状态、元数据、刷新、模型与冷却状态。
- OAuth 登录、轮询、手动回调及取消。
- Vertex 服务账号文件导入，以及管理员明确发起的原生上游请求检查。
- 原生渠道、模型、路由与客户端访问密钥。
- 日志读取、下载、清理及用量队列显式消费；不将临时队列冒充持久历史统计。
- 原生插件发现、启停、配置、商店安装与更新、额度、菜单资源代理。
- CommandCode 原有后台、账号池、额度、会话、并发、外调 API 与日志。
- 模块启停以及 CommandCode 兼容渠道注册与目录维护。
- 官方模型与套餐目录、实时来源状态、手动刷新、PostgreSQL 快照与 Redis 缓存。

额外插件资源与 API 必须提供服务端 `CPA_PLUGIN_ROUTES` 清单。任意第三方插件动态页面不是自动兼容承诺。原生高级网络功能依赖部署配置与真实验收。

## CommandCode 桥接

统一入口使用 CPA 的客户端密钥。桥接创建加密保存的内部 `ccm_nexus_` 密钥，按官方端点分别注册 `nexus-commandcode` Chat 与 `nexus-commandcode-messages` Messages 渠道，指向账号池内部网关。两种入口共享同一号池，由模块最终选号。普通模块密钥列表不显示内部桥接密钥，CPA 高级渠道配置属于管理员可读取的原生配置。

模型别名明确使用 `commandcode/<原模型ID>`；保持 CPA 原生渠道的模型名称。会话与子代理头通过 CPA 动态请求头配置传递，模块将已验证的内部访问密钥与原 CPA 客户端身份的摘要合并为亲和范围，避免不同客户端在共享内部密钥下合并会话。客户端原始密钥不写入业务日志或 Redis 映射。

原 `ccm_` 客户端使用 `/commandcode/v1` 保持原始模型名，经过 CPA 转换格式后调用官方协议。原密钥 ID 使用服务端签名传递，保留日志与会话归属；浏览器 Cookie 不发给 CPA 或模型调用端点。System One 是独立的非流式决策端点，不注册为聊天模型。

模块内部负责账号选择、Redis 原子租约、续期、取消释放、额度过滤和已确认拒绝的重试。桥接渠道关闭额外重试与冷却，避免 CPA 把一个模块上游当成单一实际账号，再次执行账号级策略。

渠道接入由管理员发起。Worker 每两分钟维护已经接入的渠道模型目录；用户在 CPA 中主动删除渠道后不会自动重建。所有列表替换会重新读取当前配置并保留其他渠道；平台内部桥接操作使用事务锁串行化。CPA 管理 API 不提供数组 CAS，同时通过外部面板编辑同一渠道列表仍需避免冲突。

## 升级与验收

独立内核固定版本与镜像摘要，候选版本先通过管理接口、原生模型协议、插件与模块回归，再更新生产；配置和凭证文件需与对应内核一起备份和回退。首版提供版本发现及升级流程，没有无条件自动替换内核。

交付检查包括类型检查、单元与真实 HTTP 测试、隔离 PostgreSQL/Redis 集成、生产构建、真实官方 CPA 本地联调与桌面/手机浏览器验收。Linux Docker/1Panel、真实上游账号与高级网络功能的部署验收分别记录，不由本地模拟调用替代。
