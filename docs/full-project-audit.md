## 已修复的问题

| 范围 | 触发条件及影响 | 修复 |
| --- | --- | --- |
| 日志持久化 | PostgreSQL 对已 stringify 的 JSON 再编码，请求、回复与 usage 实际成为字符串 | 使用结构化 JSON 参数，通过003迁移修复历史编码；不支持的Unicode保留无损json-text包装，迁移保留不可解包的内容 |
| 内核响应 | 上游断流缺少 finish 时，部分内容仍被包装为成功；末行缺少换行时丢事件 | 三协议要求真实结束事件，处理最后一行并保留失败状态 |
| 请求取消 | Chat/Messages 等待上游首包时客户端断开，取消监听尚未注册 | 在等待上游前注册取消；读取异常释放定时器 |
| 请求体限制 | chunked 请求超过配置限制时，Node 迭代器销毁连接，客户端收不到 413 | 超限后保留响应连接，返回明确的 413 |
| 慢客户端 | 下游背压等待被误计为上游空闲；实时通知没有发送上限 | 网关只对等待上游计时；通知流增加背压合并 |
| 用量真实性 | 内核按文本片段/工具次数估算 token，并在输出为零时清零真实输入 | 仅保留实际返回字段，未知用量不填估算或虚构零值 |
| 额度语义 | 每周限制可能被五小时窗口重置误清除；UI 将 limited=true 当成超限、resetAt=0 显示1970年 | 按对应窗口判断；区分窗口存在与超限，未知重置时间显示未提供 |
| 上游错误 | 非 JSON 的401无法识别凭证失效，429丢失 Retry-After | 保留HTTP分类与重试时间 |
| Key 创建 | 创建被明确拒绝后仍停在 creating，后续始终不能恢复；不完整列表可能被当成不存在 | 明确拒绝后允许重试，不确定结果保留防重复保护；校验列表完整性 |
| 同步与调度 | 同步失败重复计数；旧凭证错误影响新凭证；前2000个账号阻塞后续账号 | 去除重复记录，按凭证约束更新，使用稳定游标轮转 |
| Worker退出 | 首次调度失败遗留Worker连接；Redis离线时关闭可能无限等待 | 清理Worker/定时器，支持强制断开，普通关闭有时间上限 |
| 已保存操作 | 发布实时通知失败会使已保存操作返回失败，甚至丢失一次性Key展示 | 通知失败不覆盖持久化操作结果 |
| 管理界面 | 实时更新后表单保持旧值；导入进度切换/关闭有竞争；空名称不能保存 | 按字段同步并保留编辑内容，取消旧轮询，对齐输入约束 |
| 搜索分页 | 备注搜索缺失，日志模型中的百分号/下划线被当通配符，同时间分页不稳定 | 备注参与搜索，转义字面筛选，稳定次级排序与页码纠正 |
| 手动探测脚本 | 创建响应丢失时跳过临时Key清理，运行或清理失败仍以0退出 | 创建前记录尝试，仅按本次随机名称清理；未确认结果明确标unknown，保留核对名称，失败返回非0；8项模拟回归通过 |
| 公共图标 | 静态图标路由被管理员认证拦截，SSR超时并尝试公网回退 | 仅开放本地ph/ph.json只读路由，关闭外部回退；新增6项生产定向验证 |
| HTTP/日志保护 | 非法Origin产生500，跨协议来源未区分，部分凭证字段未脱敏 | 明确403并保留反代支持，扩充凭证字段脱敏 |

## 验证环境与边界

使用Node.js24.19.0及npm11.17.0。本地独立PostgreSQL17测试实例和Redis7.4.11实例不连接已有业务数据库。集成测试使用随机schema/前缀并自动清理。

Redis测试使用[Windows便携构建](https://github.com/redis-windows/redis-windows/releases/tag/7.4.11)，下载SHA-256已校验为ec629971d76756dd040204297f1a92f43848e7a5f4862d39426beeafcca2a2a9；这不能替代Linux Compose镜像验收。

本机Docker Desktop仍因dockerInference套接字错误无法启动。没有重置Docker、删除其数据或更改系统功能。Compose配置静态检查通过，整套Linux镜像构建、Ubuntu/1Panel反向代理、真实账号上游和真实客户端仍须在相应环境验收。

Responses仍不支持previous_response_id、store:true、服务端内建工具及完整加密reasoning状态。Messages保留usage对象及真实已知字段；若上游缺少必填数值，严格schema客户端仍有兼容边界，不能通过编造用量掩盖。依据[Anthropic SDK](https://github.com/anthropics/anthropic-sdk-typescript/blob/main/src/lib/MessageStream.ts)。

最终验证：201项测试全部通过（无跳过）、类型检查与生产构建通过、完整依赖审计0项、生产HTTP流程26项及独立浏览器交互11项通过。浏览器无控制台错误/警告/资源失败，桌面与移动截图目视复核通过。详情见[开发验证记录](development-status.md)；过程完整输出保存在被忽略的artifacts/audit-infra目录。
